# 公開前チェック（メンテナー向け）

公開設定を変更する前に確認する項目です。この文書の追加はGitHubの公開設定を変更しません。

## 今回の整理時点（2026-11-18）

- ローカルで参照できる全commitの追跡ファイルに対して、代表的なトークン形式・秘密鍵ヘッダー・
  認証情報代入パターンを検索し、該当はなかった。これは秘密情報がないことの保証ではない。
- Git履歴の著者情報にメールアドレスが含まれている。公開してよいかメンテナーが確認する。
  今回は履歴を書き換えていない。
- `doctor`はWindowsのPython実行エイリアスを起動できず失敗した。
  環境の問題として、後続のsim / build / programは実行していない。
- 今回はドキュメント・ライセンス・GitHubテンプレート・ignore設定の変更のみで、
  RTL / manifest / CLIは変更していない。CLI単体テストは今回未実行。

## ファイルと履歴

- `git status --short`と`git ls-files`で公開対象を確認する。
- 認証情報、`.env`、秘密鍵、ベンダーのライセンスファイル、個人用ログが含まれていないことを確認する。
- `build/`の生成物は追跡せず、`build/.gitkeep`だけを残す。
- 過去のcommit、別ブランチ、タグにも公開したくないファイルがないか確認する。
  `.gitignore`への追加では、追跡済みファイルや過去の履歴は消えない。
- `git log --all --format='%an <%ae>'`で公開される著者名・メールアドレスを確認する。
  今後のGit設定変更だけでは既存commitの著者情報は変わらない。
- 秘密情報が見つかった場合は無効化・再発行し、公開前に履歴を含む対応方針を決める。

## 権利と説明

- [LICENSE](../LICENSE)のMIT Licenseで公開できる内容であることを確認する。
- [外部ツール・参考元](../THIRD_PARTY_NOTICES.md)を確認し、取り込んだ外部コードがあれば
  元のライセンスと必要な権利表示を保持する。
- READMEに実験一覧、前提ハードウェア、セットアップ、検証手順が揃っていることを確認する。
- 実装済み、シミュレーション済み、ビルド済み、実機観測済みを混同しない。

## 検証と公開

- `python -m unittest discover -s tests -v`でCLIの単体テストを実行する。
- 実機検証は`doctor` → `sim <design>` → `build <design>` → `program <design>`の順で行い、
  最初の失敗で止める。programmerの成功と人が観測したLED / UART結果を分けて記録する。
- 環境がない場合は未実行であることを明記する。
- GitHubの公開範囲はメンテナーが変更し、公開後にREADME・リンク・ライセンス表示を確認する。
